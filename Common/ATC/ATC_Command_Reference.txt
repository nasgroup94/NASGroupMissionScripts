 NASG ATC — VOICE COMMAND REFERENCE
 Airport: Al Minhad (al_minhad) + AAPVE Training Range
 Generated: 2026-07-23
===============================================================================

This lists every ATC/range voice command that currently has a DEVELOPED handler
behind it (a handler function that is actually defined and produces a response).
Commands are spoken over SRS on the facility frequency; the STT bridge matches
your phrasing to an intent and DCS replies via TTS.

HOW IT WORKS
  - Speak on the facility frequency. Prefix/suffix with your callsign as normal
    (e.g. "Al Minhad Ground, HOBO11, request taxi with information Echo").
  - Phrase matching is keyword-based, so any of the listed example phrases work;
    you don't have to say them verbatim.
  - "say again" / "repeat" is understood everywhere but uses a generic fallback
    prompt (no dedicated handler) except on Ground, which repeats its last
    instruction verbatim.

NOTE ON ATIS: Ground taxi/startup requires the correct ATIS information letter
(now driven live by the MOOSE ATIS — it changes each Zulu hour). State the
current letter when requesting startup/taxi.

NOTE ON CENTER TRACKED POINTS: named points Center can vector you to that
aren't on your flight plan (tankers, bullseye, objectives, range entry
points) are defined per-mission in
"CVW-17/Persian Gulf/NATO/Persian_Gulf_ATC_TrackedPoints.lua" via
NASG_ATC:RegisterTrackedPoint — edit that file to add/remove points. That
file also registers 526 named enroute (ENR) fixes imported from the Persian
Gulf ENR waypoint template, covering the whole theater — say "request
direct <fix name>" or "request vector to <fix name>" for any of them
(e.g. "request direct ALKAD"). Fix/waypoint name lookups tolerate a small
amount of STT mis-hearing (a one-letter slip, or a name split into two
words like "bop it" for BOPIT) via a fuzzy match in
NASG_ATC:FuzzyMatchLookupKey (NASG_ATC_FlightPlans.lua) — it only accepts
an unambiguous closest match, so a badly garbled transcription still falls
through to "unable"/say-again rather than guessing among these
similarly-named fixes.

NOTE ON TANKER/AIRWING ASSETS: at fields with a MOOSE AIRWING registered to
NASG_ATC (NASG_ATC:AddAssets(...), e.g. Nellis_AFB.lua's tanker AUFTRAGs —
Jade, Coral, Pearl, Topaz, Onyx, Amber), those names are live, not static
tracked points: Center resolves them straight off whichever aircraft is
currently flying that AUFTRAG, so "request vector to Jade" (or "request
tanker" for the nearest one, no name needed) always gives a current
bearing/range plus that AUFTRAG's actual TACAN/radio frequency, and keeps
working across respawns since it isn't tied to one spawned unit's name.
Same fuzzy-match tolerance as fixes/waypoints applies to the name.

NOTE ON CALLSIGN ALIAS: forgot to rename your DCS client slot before
spawning? Say "set callsign as <callsign>" (or "change callsign to
<callsign>") on Ground and every facility will address you by the new
callsign from then on — it also becomes the lookup key for your flight
plan. The F10 "ATC Status" menu has a matching "Clear Callsign Alias" leaf
per client if you want to drop back to your original name; F10 can only
clear an alias, not set one (no free-text input on the radio menu).

NOTE ON PACKAGE FLIGHTS: callsigns that fit a <STEM><FLIGHT><POSITION>
pattern (e.g. CHECK11-14, CHECK21-24 — each a separate 4-ship) are
recognized as a package, whether you spawned directly with that callsign or
aliased into one. Only Clearance Delivery currently shares state across a
package: once any one member (usually but not necessarily the flight lead)
has received a full clearance, the rest of the package are told "you're
already covered under <callsign>'s clearance" instead of getting a
duplicate one. Ground/Tower taxi and takeoff clearances are still handled
per-aircraft.

NOTE ON NAMED PROCEDURES / ASSIGNED ROUTES: named departure/recovery
procedures ("Dream departure", "Strike recovery") are ordered sequences of
tracked points, defined per-mission in
"CVW-17/Persian Gulf/NATO/Persian_Gulf_ATC_Procedures.lua" via
NASG_ATC:RegisterProcedure. Requesting one from Clearance Delivery attaches
it to your session as an assigned route that Center can fall back to (see
Center section below) and sanity-checks at check-in/recovery. This is a
STRUCTURAL check only (do the remaining route legs still resolve to a live
point) — there is no multi-aircraft traffic deconfliction anywhere in this
codebase.

NOTE ON SQUAWK CODES: Clearance Delivery assigns a squawk code and reads it
back to you. DCS's mission-scripting environment cannot read a player's
actual transponder setting, so verbal readback is the primary check.
However, our SRS listener can also see a live Mode3/IFF transponder value if
you've set one in SRS's IFF overlay (or fly a module SRS can read the
in-cockpit transponder from) — if that value matches your assigned code,
Clearance accepts it automatically, and you don't have to speak the code
back. This is a supplementary cross-check, not a requirement: most pilots
never set an SRS IFF value, so the normal path is still to read the code
back verbally. Codes are returned to the pool automatically on landing,
crash, death, or disconnect, so a long-running server won't run out —
request clearance again after any of those and you'll get a fresh code.

 CLEARANCE DELIVERY — 126.200 AM  ("Al Minhad Clearance")
===============================================================================
Optional facility — you don't have to call Clearance before Ground/Tower;
if you never do, nothing downstream changes.

  1.  Radio check
      Say: "radio check" / "comm check" / "comms check"
      -> Replies "loud and clear."

  2.  Say again
      Say: "say again" / "repeat"
      -> Re-transmits Clearance's last instruction verbatim.

  3.  Request clearance (squawk only)
      Say: "request clearance" / "ready to copy" / "request ifr clearance"
      -> Assigns a squawk code: "squawk XXXX. Remain this frequency for
         clearance." Read back the squawk code (see #4).

  4.  Request clearance with a named route
      Say a departure/recovery procedure name and, optionally, a destination,
      e.g. "request clearance, Dream departure, destination Al Dhafra."
      -> Looks up the named procedure (see
         Persian_Gulf_ATC_Procedures.lua); if found, attaches it to your
         session as your assigned route and replies "cleared to <destination>,
         <procedure> departure/recovery, squawk XXXX." If the named
         procedure isn't found: "unable, say requested route." Read back the
         squawk code AND the procedure name.

  5.  Readback
      Say back the squawk code (and procedure name, if one was assigned).
      -> Validates; confirms, or re-issues with "negative" on a mismatch.

  6.  Check into mission
      Say: "check into mission <number>" / "check in to mission <number>" /
      "join mission <number>" / "request mission <number>",
      e.g. "check into mission one oh one."
      -> Looks up flight plans staged under
         FlightPlanRootFolder/<today>/<mission number>/ (one file per
         airframe) and attaches the one matching your aircraft type to your
         session, replacing any flight plan you already had. Replies "copy,
         checked in to mission <n>, flight plan loaded." if a match for your
         aircraft was found, "...no flight plan on file for your aircraft."
         if the mission exists but has nothing for your airframe, or
         "negative, no flight plans on file for mission <n>." if the mission
         number itself isn't recognized. If the mission number wasn't heard
         clearly: "say again, check into mission, followed by the mission
         number." Also available on the F10 menu under Select Mission (no
         voice call needed, but you must have already contacted Ground or
         Clearance at least once to have an active session).

  NOT YET IMPLEMENTED on Clearance:
    - (none — all declared intents have handlers)


===============================================================================
 GROUND CONTROL — 250.100 AM  ("Al Minhad Ground")
===============================================================================
All 17 commands below are fully implemented.

  1.  Radio check
      Say: "radio check" / "comm check" / "comms check"
      -> Replies "loud and clear."

  2.  Say again
      Say: "say again" / "repeat"
      -> Re-transmits Ground's last instruction verbatim.

  3.  Readback (taxi/EOR)
      Say: read back your taxi clearance — "...taxi to runway...", "hold short",
           "via...", "contact tower..."
      -> Validates your readback; confirms, or re-issues with "negative".

  4.  Request startup
      Say: "request startup" / "start up" / "request engine start"
      -> Checks ATIS, approves engine start, then expects a taxi request.

  5.  Request pushback
      Say: "request pushback" / "push back request"
      -> Approves pushback (with direction if stated).

  6.  Pushback complete
      Say: "pushback complete" / "push back completed"
      -> Acknowledges; expects taxi request.

  7.  Request taxi
      Say: "request taxi" / "ready to taxi" / "ready for taxi"
      -> Verifies ATIS, then (at airports that require it, e.g. Nellis)
         requires you to state your parking location in the same call --
         "west ramp", "south eor", "northeast eor", etc. -- and replies
         "say your parking location" until you do. Once stated, issues taxi
         route to the active runway with hold-short + Tower handoff.

  8.  Request taxi to EOR (end of runway / arming)
      Say: "request taxi to eor" / "request eor" / "end of runway"
      -> Same parking-location requirement as Request taxi above. Clears you
         to the EOR/arming area (falls back to normal taxi if EOR is
         unavailable at this field).

  9.  EOR complete
      Say: "eor complete" / "arming complete" / "ready at eor"
      -> Clears you from EOR to the runway/hold-short with Tower handoff.

  10. Request progressive taxi
      Say: "progressive taxi" / "request progressive"
      -> Issues step-by-step taxi, one taxiway at a time.

  11. Holding short / ready for departure
      Say: "holding short" / "ready for departure" / "ready at the hold short"
      -> Hands you off to Tower frequency.

  12. Request taxi back
      Say: "taxi back" / "return to ramp" / "return to parking"
      -> Routes you from your current position back to parking.

  13. Request parking
      Say: "request parking" / "parking" / "taxi to parking"
      -> Same as taxi-back (routes to parking).

  14. Request rearm/refuel
      Say: "rearm" / "refuel" / "taxi to rearm"
      -> Directs you to the maintenance ramp.

  15. Abort taxi
      Say: "abort taxi" / "aborting taxi" / "return to ramp"
      -> Routes you back to parking.

  16. Ground emergency
      Say: "emergency" / "brake failure" / "engine fire" / "ground emergency"
      -> Acknowledges; tells you to hold position.

  17. Set callsign alias
      Say: "set callsign as <callsign>" / "set callsign to <callsign>" /
           "change callsign as <callsign>" / "change callsign to <callsign>"
      -> Adopts the new callsign for all facilities (see NOTE ON CALLSIGN
         ALIAS above); replies "copy, <callsign>, callsign updated."


===============================================================================
 TOWER — 310.500 AM  ("Al Minhad Tower")
===============================================================================
14 implemented commands.

  1.  Readback (takeoff/landing)
      Say: "line up and wait" / "cleared for takeoff" / "cleared to land" /
           "go around"
      -> Validates your readback against the runway issued and, on takeoff
         clearance, the climb altitude assigned (see #2/#3); "negative" +
         re-issue on a mismatch.

  2.  Departure check-in
      Say: "holding short" / "holding short runway..." / "ready for departure"
      -> Assesses the runway and issues continue-hold / line-up-and-wait /
         cleared-for-takeoff. Takeoff clearance includes "climb and maintain
         X" (flight plan's departure-waypoint altitude, else the airport's
         configured default) before the runway/cleared-for-takeoff clause;
         read back the altitude along with the runway.

  3.  Request takeoff
      Say: "request takeoff" / "ready for takeoff" / "ready to depart" / "ready"
      -> Runway assessment and takeoff clearance, same climb-altitude clause
         and readback requirement as #2.

  4.  Abort takeoff
      Say: "abort takeoff" / "aborting takeoff"
      -> Acknowledges; exit the runway and contact Ground.

  5.  Inbound full stop
      Say: "inbound full stop" / "inbound landing" / "request landing" /
           "full stop landing"
      -> Issues pattern entry (downwind / straight-in / initial) + reporting.

  6.  Inbound touch-and-go
      Say: "touch and go" / "touch-and-go" / "inbound touch and go"
      -> Pattern/downwind entry with report instruction.

  7.  Inbound overhead
      Say: "inbound overhead" / "request overhead" / "initial for overhead"
      -> "Enter initial Runway X, report initial."

  8.  Report initial
      Say: "initial" / "report initial" / "at initial"
      -> "Break approved, report downwind."

  9.  Report downwind
      Say: "downwind" / "report downwind" / "midfield downwind"
      -> Issues landing clearance (with wind).

  10. Report base
      Say: "base" / "report base" / "turning base"
      -> Cleared to land.

  11. Report final
      Say: "final" / "on final" / "five mile final"
      -> Cleared to land.

  12. Clear of runway
      Say: "clear of runway" / "runway vacated" / "off the runway"
      -> Transfers you to Ground.

  13. Going around / missed approach
      Say: "going around" / "go around" / "missed approach"
      -> "Fly runway heading, report upwind."

  14. Request closed traffic
      Say: "closed traffic" / "request closed traffic" / "stay in the pattern"
      -> "Closed traffic approved Runway X, report downwind."

  NOT YET IMPLEMENTED on Tower (declared but no handler -> generic prompt):
    - "radio check" (HandleRadioCheck not defined for Tower)
    - "request route/departure/recovery..." (HandleRouteRequest not defined)
    - "say again" (no dedicated handler)

 CENTER — 251.000 AM  ("Emirates Center")
===============================================================================
16 implemented commands.

  1.  Radio check — "radio check" / "comm check"
      -> "loud and clear."

  2.  Check-in — "checking in" / "with you" / "level"
      Say your position, current altitude, and goal altitude, e.g. "Emirates
      Center, HOBO11, 20 west of Al Minhad, climbing through 8 thousand for
      1 6 thousand."
      -> "Radar contact" + your live altitude (authoritative, not the stated
         one); reassigns/confirms an altitude — your stated goal if given,
         else the flight plan's active-leg altitude if on file — as "climb/
         descend/maintain and maintain X." Read back the assigned altitude
         (see #16). If Clearance Delivery assigned you a route, Center also
         does a structural check that its remaining legs still resolve to a
         live point (not a traffic check) and appends "advise, unable <leg>,
         resolve at own discretion" if one doesn't.

  3.  Request flight following — "request flight following" / "request advisories"
      -> Same as check-in, including altitude reassignment.

  4.  Request direct — "request direct" / "proceed direct"
      -> Clears you direct to a flight-plan fix, or a registered tracked
         point (see Persian_Gulf_ATC_TrackedPoints.lua) if no matching fix is
         on your flight plan; if you name no fix at all and Clearance
         Delivery assigned you a route, defaults to that route's next leg.
         Arms a readback.

  5.  Request vector to waypoint — "request vector" / "vectors to..."
      -> Bearing/distance vector to the requested flight-plan waypoint, else
         a registered tracked point (bullseye, objective, etc.), else a
         live named tanker/AWACS asset (e.g. "request vector to Jade") if
         the name matches one being flown right now (see NOTE ON TANKER/
         AIRWING ASSETS below); same assigned-route-leg fallback as #4 when
         no name is given.

  6.  Request range — "request range" / "vector to range" / "range work"
      -> Vectors to a range waypoint on your flight plan ("unable" if none).

  7.  Request tanker — "request tanker" / "request AAR" / "vector to tanker"
      -> Vector to nearest active tanker + TACAN + radio frequency.

  8.  Request recovery — "request recovery" / "vectors home"
      -> Approves recovery with a "descend and maintain X" clause (flight
         plan's recovery-waypoint altitude, else the airport's configured
         recovery descent default) before handing you off to arrival Tower;
         read back the descent altitude (see #16). Arrival airport falls
         back to a Clearance-assigned route's stated destination if your
         flight plan has none on file. Same structural route-leg check as
         check-in (#2) applies here too.

  9.  Request divert — "request divert" / "request alternate"
      -> Clears direct to the flight plan's divert field ("unable" if none).

  10. Request frequency change — "frequency change" / "request switch"
      -> Approves; directs you to Tower.

  11. Request MARSA — "request marsa" / "request own separation"
      -> Activates MARSA; reads approved altitude block if defined.

  12. Cancel MARSA — "cancel marsa" / "resume atc separation"
      -> Deactivates MARSA; "ATC separation resumed."

  13. Request block altitude — "request block altitude" / "request block"
      -> Approves a min/max altitude block ("unable" if none resolvable).

  14. Request VFR on top — "request vfr on top" / "vfr on top"
      -> Approves; maintain own terrain clearance/nav.

  15. Course check — "course check" / "am i on course" / "on course"
      -> On-course + distance remaining, or off-course side/distance + rejoin
         heading.

  15a. Established on radial (report) — "established on the 346 radial" /
       "established radial" / "on the radial"
      -> Pilot self-report (vs. #15's pilot-initiated request) that they're
         established on a Clearance-assigned route's radial-intercept leg
         (e.g. DREAM FOUR's BLD R-346). Confirmed against the leg's actual
         target radial/DME/altitude, not the number spoken (STT mis-hears);
         "roger, radar contact on <fix>" if correct, "negative, N degrees
         [left/right] of <fix>" if not, "unable" if no radial leg is active.

  16. Readback — "proceed direct" / "maintain" / "climb" / "descend"
      -> Validates a pending Center instruction, including the altitude
         assigned at check-in (#2/#3) or recovery (#8); "negative" +
         re-issue on a mismatch.

  NOT YET IMPLEMENTED on Center:
    - "say again" (no dedicated handler -> generic prompt)

===============================================================================
 AAPVE TRAINING RANGE
===============================================================================
The range is controlled BOTH by voice (over AWACS 251.500 AM) and by the F10
radio menu "A/A RANGE SETUP" (BLUE). Voice and menu are kept at parity — both
call the same underlying range functions.

Voice control requires NASG_ATC + AWACS to be loaded (registered to airport
"al_minhad"). If NASG_ATC is absent, the range falls back to F10-menu-only
control with standalone TTS.

-------------------------------------------------------------------------------
 A. PILOT VOICE INTENTS WITH A RANGE HANDLER (spoken to AWACS)
-------------------------------------------------------------------------------
  - Check in     — "check in" / "on station" / "cap check in" /
                   "request alpha check"
                   -> Assigns a CAP station/package; alpha check + angels block.
                      (In practice mode, starts a practice session.)
  - Picture      — "picture" / "new picture" / "tactical picture"
                   -> BULLSEYE picture of your package's live hostile / new pic.
  - Commit       — "commit" / "committing north"        -> scores commit call.
  - Targeted     — "targeted" / "sorted"                -> scores targeted call.
  - Say threat   — "threats" / "threat check"           -> scores threat ack.
  - Defending    — "defending" / "missile in the air"   -> scores defensive ack.
  - Fox          — "fox one/two/three" / "guns guns guns"
                   -> detects missile type; scores shot range/aspect/envelope.
  - Merge        — "merge" / "merging"                  -> commits package FSM.
  - Splash       — "splash" / "good kill"               -> confirms kill, retasks
                   package back to CAP.
  - Combat recovery — "rtb" / "request recovery"        -> disengages package for
                   home-plate vector.
  - Tanker       — "request tanker" / "need gas"        -> BULLSEYE vector to
                   nearest tanker.
  - Check out    — "good day" / "checking out"          -> closes out package /
                   ends practice session.
  - Practice ready — "ready" / "next run"               -> spawns next practice
                   intercept.

  (Bogey dope / BRAA / declare / alpha check / vector-to-target also return LIVE
   range contact data — the AWACS formats the reply, the range supplies the
   bullseye/BRAA/aspect.)
